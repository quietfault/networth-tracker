## Проект собран и задеплоен (2026-07-09)

Вся первая версия уехала одним коммитом `d3df7e4` — 47 файлов: React с
TypeScript, Supabase со схемой и RLS, снимки капитала, автобаланс кошельков
(ETH/EVM, BTC, SOL), деплой на GitHub Pages через GitHub Actions. Опирался на
опыт `habit-tracker` — первого проекта портфолио с Supabase и Pages.

**Два коммита того же дня — не работа, а следы борьбы с деплоем** (`e3ccc77`,
`ddd8c99` с сообщениями «trigger rebuild»). За ними две ловушки GitHub Actions,
разобранные в `DECISIONS.md`, и обе стоили реального времени:

- Windows Git Credential Manager кэшировал старый PAT без scope `workflow`, и
  GitHub отклонял пуш файлов `.github/workflows/*`.
- Секреты `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` легли в
  environment-scoped секреты окружения `github-pages`, а job `build` в
  `deploy.yml` этого окружения не объявляет — секреты были физически невидимы
  шагу сборки. Сборка при этом оставалась зелёной, а в бандл тихо уезжал
  `throw new Error('Missing VITE_SUPABASE_URL...')` вместо настоящего URL.

**Урок, который стоит помнить не только здесь:** зелёный прогон workflow ничего
не говорит о работоспособности бандла, если ошибка не падает при сборке, а тихо
становится `undefined` в рантайме. Единственная надёжная проверка — скачать
настоящий бандл с прода и найти в нём конкретную строку.

## Кошельки: три поломки, одна причина (2026-08-18)

Коммит `85e58df`. Проверка живьём показала три бага сразу: solana-кошелёк считал только SOL,
эфирный отдавал ошибку API, у BTC не показывались Руны. Причина под всеми тремя
одна — источники балансов не были изолированы друг от друга, а часть данных не
запрашивалась вовсе.

Solana получил `getTokenAccountsByOwner` по обеим программам (SPL Token и
Token-2022), Ethereum — последовательный опрос сетей вместо `Promise.all`,
который не влезал в 5 запросов/сек бесплатного тарифа Etherscan, Bitcoin —
явное сообщение вместо молчаливого пропуска Рун при незаданном ключе UniSat.
Логика балансов уехала в `src/lib/walletAssets.ts`, общий для `/wallets` и формы
среза.

**Что осталось незакрытым:** ERC-20 токены на EVM-сетях по-прежнему не
подтягиваются — список токенов на адресе в Etherscan V2 доступен только на
платном тарифе.

## Приложение приведено к брендбуку и получило имя (2026-08-18)

Коммит `2906ec1`. Трекер жил на стилях от шаблона `npm create vite` — фиолетовый акцент, инлайн-
стили в компонентах, английское «Net Worth Tracker» при русском интерфейсе.
Оформление переведено на брендбук quietfault 1.0 из репозитория маркетинга:
токены и знаки скопированы в репозиторий вендорными копиями, шрифты Inter и
JetBrains Mono самохостятся через `@fontsource` (CDN брендбук запрещает —
отдаёт IP посетителя), тёмная тема стала темой по умолчанию, светлая —
переключателем в шапке.

Приложение называется **«Срез»** — по единице данных, с которой оно и работает.
Знак «Пересборка» встал в шапку, на экран входа и в фавикон; «Разлом» остался в
своей роли — буллет списка предупреждений и разделитель между кошельками.

Развилки — в `DECISIONS.md`: почему копия бренда, а не сабмодуль; почему
системная тема намеренно игнорируется; почему пирог разбивки набран одной
тональностью акцента, а не палитрой панели маркетинга.

**Обе записи этого дня лежат в ветке `claude/wallet-errors-solana-eth-btc-lnt3nx`
и в `main` на момент записи не влиты** — прод показывает версию до них.

## Живые API оказались недоступны из облачной сессии (2026-08-18)

Правки кошельков писались и сдавались, ни разу не постучавшись в настоящий API.
Прямые запросы к `api.etherscan.io`, `solana-rpc.publicnode.com` и
`open-api.unisat.io` не уходят: прокси облачной сессии отдаёт 403 на CONNECT —
этих хостов нет в списке разрешённых.

Заменой стали 16 проверок на замоканном `fetch` по всем разобранным формам
ответов и отказов — частичный отказ EVM-сети, исчерпанный лимит Blockchair,
401 от UniSat, две токен-программы Solana, слияние нескольких аккаунтов одного
минта, — плюс скриншоты интерфейса с замоканным Supabase.

Это покрытие форматов, а не доказательство работоспособности: настоящий ответ
может отличаться от того, что мы считаем настоящим ответом. Живая проверка
осталась на владельце и на 20 августа не сделана. Почему сдавали так, а не
дожидались владельца в середине сессии — `DECISIONS.md`.

## Решение пересобрать «Срез» в дашборд (2026-10-05)

Владелец поставил задачу на месяц: полноценный дашборд вместо застрявшего
трекера. Выяснилось главное: застрял не код, а использование — в базе не было
истории с 2017 года, и любой аналитике не на чем работать. Сессия вопросами
собрала спецификацию (`docs/superpowers/specs/2026-10-05-srez-rebuild-design.md`):
капитал в трёх мерах — ₽ по курсу USDT на P2P, $, BTC; модель «справочник мест +
суммы» вместо четырёх жёстких категорий; импорт истории через шаблон, под
который владелец сам собирает лист формулами (19 крипто-таблиц с меняющейся
логикой парсером не разобрать); дашборд «пульт в две колонки»; пересборка в
ветке `rebuild` на старом фундаменте. Евро считаются через P2P-доллар (поправка
владельца 2026-10-06). Шаблон импорта `docs/import/import-template.xlsx` проверен
в Excel. Пункты августовского «не сделано» — заглушка `/snapshot/:id`, ERC-20 на
EVM, экспорт, импорт из Excel — вошли в план пересборки, а не остались отдельными
задачами.
