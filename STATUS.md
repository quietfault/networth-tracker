## Не сделано

- **ERC-20 токены на EVM-сетях** — подтягивается только нативная монета

  эндпоинт; бесплатная альтернатива Blockscout не проверялась.
- **Экспорт в JSON.**
- **Импорт исторических данных из Excel** с 2017 года.

## Открытая проблема: балансы не проверены на живых API

**Симптом:** правки кошельков написаны и покрыты офлайн-проверками, но ни один
запрос к настоящему API из этой сессии не ушёл.

**Что пробовали:** прямые запросы к `api.etherscan.io`, `solana-rpc.publicnode.com`
и `open-api.unisat.io` — прокси облачной сессии отдаёт 403 на CONNECT, эти хосты
не в списке разрешённых.

**Чем заменили:** 16 проверок на замоканном `fetch` по всем разобранным формам
ответов и отказов (частичный отказ EVM, лимит Blockchair, 401 UniSat, две
программы SPL, слияние минтов) плюс скриншоты интерфейса с замоканным Supabase.

**Что осталось сделать руками:** открыть `/wallets` с настоящими ключами
Etherscan и UniSat и сверить три вещи — solana-кошелёк показывает SPL-токены
кроме SOL, эфирный не падает целиком, у BTC-адреса видны Руны (или строка
«UniSat API key не задан», если ключа нет).

## 🔴 Заблокировано на владельце

| Шаг | Где делать | Зачем |
|---|---|---|
| Закрыть регистрацию | Supabase → Authentication → Sign In / Providers → выключить «Allow new users to sign up» | Сейчас любой посетитель заводит аккаунт в твоей базе. Данные закрыты RLS, но плодить аккаунты незачем. Две минуты |
| Влить ветку `claude/wallet-errors-solana-eth-btc-lnt3nx` в `main` | GitHub, PR или прямой мерж | Пока не влито — прод со старым оформлением и старыми багами кошельков |
| Завести ключ UniSat, если нужны Руны | developer.unisat.io → в приложении Настройки → UniSat API key | Без ключа Руны не подтягиваются: теперь это видно строкой, а не молча |
| Проверить `/wallets` на живых данных | Сам сайт после мержа | Единственное, что нельзя сделать из облачной сессии, — см. «Открытая проблема» |

## Ближайшие три шага

1. Влить ветку в `main` и проверить `/wallets` живьём с настоящими ключами.
2. Закрыть регистрацию в Supabase.
3. Доделать `/snapshot/:id` — сейчас заглушка, и это единственная страница,
   которую можно кому-то показать.

## Про ключи

`anon key` в этом проекте безопасен по дизайну: он и должен быть публичным, всё
закрыто политиками RLS на стороне базы. `.env` в `.gitignore`, `.env.example`
коммитится — здесь порядок, ничего чинить не надо. Ключи Etherscan и UniSat
лежат в таблице `settings` в базе, не в коде.
