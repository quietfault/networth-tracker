# «Срез» — пересборка в финансовый дашборд

**Дата:** 2026-10-05 · **Ветка:** `rebuild` · **Срок:** до 2026-11-05

Спецификация собрана в сессии 2026-10-05 вопросами и ответами владельца.
Почему выбраны модель и способ пересборки — `DECISIONS.md`, две последние записи.

---

## Цель и критерий готовности

«Срез» заменяет Excel, который владелец ведёт с 2017 года. Дашборд показывает
капитал в трёх мерах — ₽, $, BTC — и где он лежит.

Сделано, когда **оба** утверждения верны и проверены владельцем руками:

1. Настоящая история с 2017 года загружена в приложение, и у каждой строки,
   где итог приложения разошёлся с итогом Excel, есть объяснение.
2. Срез за ноябрь 2026 введён в приложении, а не в Excel.

Пользователь в этом месяце — только владелец. Архитектура (RLS по `user_id`)
многопользовательская и такой остаётся, но онбординга и открытой регистрации нет.

## Что осталось от старого кода и что пишется заново

|---|---|

## 1. Данные

### Таблицы (Supabase, у каждой `user_id` + RLS + `GRANT` только `authenticated`)

**`places`** — справочник мест, повторяет лист «Места» шаблона импорта.

| Поле | Тип | Примечание |
|---|---|---|
| `name` | text | уникально в пределах пользователя |
| `category` | text | свободный текст, новая категория появляется сама |
| `currency` | text | `RUB` · `USD` · `EUR` · `BTC`; USDT записывается как USD |
| `form` | text | `cash` · `noncash` · `none`; в шаблоне это «нал» / «безнал» / «—», импорт переводит |
| `sort_order` | int | порядок вывода |
| `chain`, `address` | text, nullable | заполнены только у мест-кошельков: `ethereum` (все EVM), `bitcoin`, `solana` |

Валюту места **нельзя менять после первой ненулевой суммы** в любом срезе —
иначе история молча пересчитается в другой валюте. Имя, категория, форма и
порядок — живые: правка перегруппировывает всю историю.

**`snapshots`** — срез.

| Поле | Тип | Примечание |
|---|---|---|
| `period` | text `YYYY-MM` | уникален с `user_id`: один срез в месяц |
| `snapshot_date` | date | |
| `usdt_rub` | numeric | курс USDT на P2P, **всегда руками** |
| `eur_rub` | numeric | подставляется (курс ЦБ через зеркало `cbr-xml-daily.ru/daily_json.js`, проверено 2026-10-06), правится руками |
| `btc_usd` | numeric | подставляется (CoinGecko), правится руками |
| `entries` | jsonb | `[{ placeId, amount, detail? }]`; `detail` — монеты кошелька |
| `reported_total_rub` | numeric, nullable | итог Excel; есть только у импортированных |
| `source` | text | `import` · `manual` |

Суммы и курсы среза неизменяемы: функции `update` в слое данных нет.

**`settings`** — `unisat_api_key`, `coingecko_api_key` (оба необязательны).
Ключ Etherscan уходит вместе с самим Etherscan. Таблица `wallets` уходит:
кошелёк — это место с адресом.

### Расчёт — один модуль чистых функций под тестами

Пересчёт суммы места в рубли по курсам **этого же** среза:

| Валюта | В рубли |
|---|---|
| RUB | × 1 |
| USD | × `usdt_rub` |
| EUR | × `eur_rub` |
| BTC | × `btc_usd` × `usdt_rub` |

Итог в $ = итог ₽ / `usdt_rub`; итог в BTC = итог $ / `btc_usd`.

Правило совпадает с формулой колонки «Итог ₽» шаблона
`docs/import/import-template.xlsx`. Тест на вердикт: модуль, применённый к шести
строкам шаблона, даёт ровно те итоги, что посчитал Excel. Первая строка —
5 427 000 ₽, проверена 2026-10-05 открытием файла в Excel и ручным пересчётом.

### Источники балансов кошельков

Проверено живыми запросами с машины владельца 2026-10-05; CORS открыт везде,
ключ не нужен, если не сказано иное.

| Сеть | Нативная монета | Токены | Цена |
|---|---|---|---|
| Solana | Jupiter `lite-api.jup.ag/ultra/v1/holdings` | там же; флаг `excludeFromNetWorth` отсекает мусор | Jupiter `lite-api.jup.ag/price/v3` |
| EVM: Ethereum, Optimism, Base, Arbitrum, Polygon | publicnode RPC `eth_getBalance` | Blockscout `/api/v2/addresses/{a}/token-balances` (Optimism — `explorer.optimism.io`) | `exchange_rate` из Blockscout, иначе CoinGecko по контракту |
| EVM: BNB, Avalanche | publicnode RPC | **руками** — у Blockscout нет экземпляров | — |
| Bitcoin | mempool.space `/api/address/{a}`: `funded_txo_sum − spent_txo_sum` | Руны — UniSat (ключ) | CoinGecko `simple/token_price/ordinals` по `runeid` |

Что отказало и почему ушло:

- **Etherscan V2** — бесплатный ключ больше не обслуживает BNB, Optimism, Base,
  Avalanche (скриншот владельца 2026-10-05).
- **publicnode Solana `getTokenAccountsByOwner`** — «Request blocked» и
  «Indexed requests require a personal token». Отсюда «Solana показывает только SOL».
- **Blockchair** — IP владельца в бане за превышение бесплатного лимита.

Ограничение CoinGecko без ключа: **один контракт на запрос**. Запросы по
контрактам идут последовательно; с ключом Demo — пачкой.

**Правило кошельков:** «подтянуть» только **предлагает** сумму места. Сохранение
среза никогда не зависит от ответа API. Каждый источник отказывает независимо и
показывается строкой рядом с тем, что загрузилось. Пыль (суммы, которые в
выбранной мере округляются до нуля) не выводится экспоненциальной записью.

## 2. Экраны

Меню: **Дашборд · Новый срез · Срезы · Места · Импорт · Настройки**. Роутинг —
HashRouter, как сейчас.

**Дашборд** — «пульт в две колонки», вариант 1б из сессии.

- Левая колонка: итог с переключателем ₽ / $ / BTC; изменение за месяц и за год;
  расстояние от исторического максимума в выбранной мере; график итога с первого
  среза; валютная корзина (доли RUB / USD / EUR / BTC) сейчас; нал / безнал /
  прочее сейчас.
- Правая колонка: места по категориям — сумма категории и каждого места,
  мини-тренд за 12 месяцев. Места, нулевые в последнем срезе, свёрнуты в строку
  «закрытые (N)».
- Долей категорий нет — владелец отказался от них явно.
- На ширине телефона колонки складываются в одну.

**Новый срез.**

- Дата; курс P2P руками; EUR/RUB и BTC/USD подставлены, правятся.
- Места по категориям, суммы предзаполнены из предыдущего среза.
- У мест-кошельков кнопка «подтянуть»; ошибки — строкой, сохранению не мешают.
- Новое место добавляется прямо в форме.
- Итог в трёх мерах пересчитывается на ходу.
- Месяц, за который срез уже есть, сохранить нельзя — понятный текст, а не код Postgres.

**Срезы** — список: дата, итог, источник, отметка сверки. По клику — **просмотр
среза** (`/snapshot/:id`): суммы по местам, курсы, для импортированных — «итог
Excel ↔ итог приложения» и разница.

**Места** — справочник: имя, категория, форма, порядок, сеть и адрес. Валюта
заблокирована после первой ненулевой суммы.

**Импорт.**

- Принимает `.xlsx` формата шаблона: листы «Места» и «Срезы», строка заголовков
  на «Срезах» — та, где в колонке A стоит «Дата». Колонки «USDT/RUB», «EUR/RUB»,
  «BTC/USD», «Итог ₽», дальше места.
- Файл читается **в браузере** и не уходит никуда, кроме базы владельца.
- Предпросмотр: какие места новые, какие совпали с существующими; каждая строка
  с отметкой сверки; расхождение больше 1 ₽ — красным.
- Ошибки формата (место в «Срезах» без строки в «Местах», неизвестная валюта,
  два среза в одном месяце, пустой курс) показываются до записи и запись блокируют.
- Запись — одной кнопкой. Месяцы, которые уже есть в базе, не перезаписываются
  и показываются отдельным списком.

**Настройки** — ключ UniSat, ключ CoinGecko (необязательно), тема.

## 3. План, проверка, разделение труда

| Неделя | Работа | Проверка |
|---|---|---|
| 1 · до 12.10 | Схема БД, модуль расчёта, импорт со сверкой | Шаблон загружается, шесть итогов совпадают с Excel до рубля |
| 2 · до 19.10 | Дашборд, список срезов, просмотр среза | Пульт на данных шаблона, если лист владельца готов — на его данных |
| 3 · до 26.10 | Новый срез, Места, кошельки на новых источниках | Настоящие адреса владельца: SOL с токенами, EVM, BTC, руны с ценами |
| 4 · до 05.11 | Оформление по брендбуку, слияние в `main`, деплой, запас | Ноябрьский срез на проде |

Импорт первым, потому что сборка листа в Excel — самая длинная цепочка месяца и
целиком на владельце.

**Как проверяется:**

- Расчёт и разбор файла — тестами (vitest; в `package.json` сейчас нет тестового
  скрипта, он добавляется первым шагом). Тест сначала падает; при намеренной
  поломке смотрится `git diff`, что поломка применилась.
- Тест проверяет вердикт («строка сошлась / разошлась»), а не только числа.
- Каждый экран — открывается на localhost и прокликивается.
- Внешние API — живыми запросами, как 2026-10-05.

**На владельце:**

1. Неделя 1 — выполнить новую схему в Supabase → SQL Editor. Схема **удаляет**
   старые таблицы; перед запуском — отдельное напоминание. Начать собирать свой
   лист под шаблон.
2. Неделя 2 — загрузить свой лист через Импорт, разобрать красные строки.
3. Неделя 3 — публичные адреса кошельков; по желанию ключ CoinGecko Demo.
4. Неделя 4 — ввести ноябрьский срез.

**Риски.** Лист владельца не готов к неделе 2 — пульт дольше живёт на шаблоне,
план не ломается. Библиотека чтения `.xlsx` в браузере — выбирается в плане
реализации: у SheetJS версия в npm устарела.

## Не в этом месяце

- Разложение прироста на «я сам» и «курсы» — модель уже хранит курсы, добавляется
  страницей без переделки данных.
- Токены на BNB и Avalanche.
- Восстановление состава кошельков на прошлые даты по блокчейну.
- Доступ для других людей: онбординг, регистрация.
- Экспорт в JSON.
