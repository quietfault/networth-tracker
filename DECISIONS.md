# DECISIONS.md — networth-tracker

Зачем этот файл: код показывает, что сделано. Он не показывает, какие варианты
были отвергнуты и почему. Ниже — развилки из чата с Claude Code, которые иначе
умерли бы вместе с архивом сессии.

---

## Хранение данных: Supabase, а не localStorage

**Отвергнуто:** чистый localStorage (был явно прописан в исходном CLAUDE.md
в разделе "Важные ограничения" — "никакого бэкенда, никакой авторизации").

**Выбрано:** Supabase (Postgres + Auth) с RLS по `user_id = auth.uid()`.

**Почему:** нужен доступ с нескольких устройств (телефон + комп), а
localStorage привязан к одному браузеру. Сам CLAUDE.md на момент старта
противоречил себе — в разделе "Стек" уже была фраза про "минимальную
авторизацию как в проекте с привычками", но в "Ограничениях" это
перечёркивалось. Решили в пользу Supabase, документ поправлен по ходу.

**Публичность репозитория и sitецена этого решения:** GitHub Pages — статика
без сервера, значит сам фронтенд физически открыт всем по URL. Это ок именно
потому что данные защищены не секретностью кода, а RLS + логином: без сессии
Postgres отдаёт `permission denied` на уровне грантов, а не просто пустой
список (см. ниже).

---

## Способ входа: email+пароль, а не magic link

В соседнем проекте (с привычками) стоит magic link. Здесь сознательно выбрали
пароль — без объяснения предпочли просто "email + пароль" при прямом выборе
между двумя вариантами. Если понадобится сменить — это чисто фронтовая правка
в `src/pages/Login.tsx` + `src/contexts/AuthContext.tsx`, схема БД не завязана
на способ входа.

---

## Отдельный Supabase-проект, а не общий с другими приложениями

**Отвергнуто:** переиспользовать Supabase-проект от привычек.

**Почему:** один аккаунт Supabase = много независимых проектов, как
организация на GitHub с несколькими репозиториями. Данные networth не должны
физически лежать в той же базе, что и привычки — разные жизненные циклы,
разные RLS-политики, никакой причины шарить.

---

## TypeScript, а не JS

Явный выбор при старте: структура снимка (Snapshot) вложенная и с полями вроде
`amount`/`priceUSD`, где опечатка в поле — тихий баг в подсчёте networth, а не
ошибка на этапе разработки. Типы окупаются уже на данных такой формы.

---

## Snapshot.assets — один jsonb-блоб, а не нормализованные таблицы

**Отвергнуто (неявно, не обсуждалось отдельно, но стоит зафиксировать):**
раскладывать banks/crypto/inventory/physical по отдельным SQL-таблицам с
foreign key на snapshot_id.

**Выбрано:** `snapshots.assets jsonb`, структура — прямое отражение
концептуальной модели из CLAUDE.md.

**Почему:** это личный инструмент одного пользователя, не аналитическая
система с произвольными джойнами. Категории активов и так гетерогенны
(у крипто-холдинга есть `tokens[]`, у банка — нет), нормализация добавила бы
3-4 таблицы и миграции ради запросов, которых никогда не будет. jsonb даёт
гибкость строго там, где она нужна (произвольные токены в кошельке), и не
мешает `total_usd`/`usd_rub`/`period` быть обычными индексируемыми колонками.

## RLS + явный GRANT только для `authenticated`, не для `anon`

**Найденная ловушка:** Supabase не даёт новым таблицам привилегий по
умолчанию. Первая проверка через анонимный REST-запрос вернула не пустой
массив (как ожидалось бы от одной только RLS), а `42501 permission denied for
table wallets` — то есть Postgres резал запрос ещё до применения RLS-политик.

**Решение:** `grant select, insert, update, delete on wallets, snapshots,
settings to authenticated;` — и **сознательно не** выдавать те же права
`anon`. RLS обычно и так отфильтровала бы для анонима все строки (`auth.uid()
= user_id` → false для null uid), но здесь двойная защита: даже гипотетическая
дыра в политике не даст анониму ничего прочитать, потому что у роли просто нет
доступа к таблице на уровне грантов.

---

## HashRouter, а не BrowserRouter + 404.html-трюк

**Отвергнуто:** BrowserRouter с классическим GitHub Pages SPA-хаком
(404.html редиректит на index.html через sessionStorage).

**Выбрано:** HashRouter (`/#/wallets` вместо `/wallets`).

**Почему:** GitHub Pages — статика без серверных рефрейзов. 404-трюк работает,
но добавляет edge-case (query-параметры иногда теряются при редиректе) и лишний
файл инфраструктуры. Для личного инструмента некрасивый `#` в URL — не цена,
за которую жалко платить.

---

## Автобаланс кошельков: только ETH/EVM, BTC, SOL — не всё подряд

**Отвергнуто:** одинаковый уровень автоматизации для всех активов.

**Выбрано:**
- EVM-адреса (Ethereum + топ-7 сетей) — через Etherscan V2, один ключ на все
  сети (`chainid` параметр)
- BTC — нативный баланс через Blockchair (без ключа, лимит ~30 req/day)
- BTC Runes — через UniSat Open API (нужен свой бесплатный ключ)
- Solana — нативный SOL через публичный RPC (`solana-rpc.publicnode.com`,
  не официальный `api.mainnet-beta.solana.com` — тот блокирует браузерные
  запросы по CORS)
- CEX-балансы (Binance/Bybit) и NFT — **сознательно оставлены ручными**,
  автоматизация через API бирж потребовала бы хранить API-ключи с торговыми
  правами, что несоразмерно риску для личного трекера

**Почему именно этот набор сетей:** пользователь явно попросил "топ-10
блокчейнов, на которых могут быть деньги" вместо изначального минимального
набора (только Ethereum), аргумент — Etherscan v2 даёт мультичейн почти
бесплатно через один и тот же ключ, грех не воспользоваться.

## Wallets page: BTC-нативный баланс и Runes запрашиваются независимо

**Найденный баг при живом тестировании:** изначальная реализация делала
`await fetchBtcBalance()` и `await fetchRuneBalances()` последовательно в одном
try/catch. Blockchair (30 req/day) исчерпал лимит раньше, чем мы успели
протестировать Runes — и из-за одного `throw` терялись оба результата, хотя
UniSat отработал бы нормально.

**Исправление:** каждый источник в собственном try/catch, ошибка одного
рендерится как отдельная строка с текстом причины, не блокируя данные другого.
Общий принцип для этой страницы: **частичный успех должен показываться как
частичный успех**, а не схлопываться в общую ошибку.

## UniSat: `spacedRune`, а не `symbol`, как отображаемое имя Руны

Первая реализация (до живой проверки с реальным ключом) была best-effort по
описанию полей — предполагали `runeSymbol`/`symbol` как тикер. Живой запрос
2026-07-09 показал: `symbol` — декоративный однобуквенный глиф (`¤`, `⧉`), не
имя. Переключились на `spacedRune` (например `BABYODIN•ID•NWKQ•ODIN`) как
единственное человекочитаемое поле в ответе.

## Предзаполнение формы снимка: разная стратегия для кошельков и остального

**Кошельки (self-custody из `/wallets`):** пересобираются заново каждый раз из
таблицы `wallets` (источник истины), а не копируются из прошлого снимка — так
удаление/добавление кошелька в `/wallets` сразу отражается в новой форме.
Токен-суммы внутри каждого кошелька при этом берутся из прошлого снимка как
стартовое значение (по совпадению `address`), пока не нажата "Обновить
балансы".

**Банки/инвентарь/физика/CEX:** не имеют отдельной таблицы-источника (в
отличие от кошельков), поэтому единственный способ не вбивать всё заново —
скопировать соответствующие строки из **последнего** снимка. Выбрано
пользователем явно при прямом вопросе "предзаполнять или пустая форма" —
аргумент: банки и товарные позиции не меняются от снимка к снимку, меняются
только суммы.

## Итог в USD: только RUB и USD, без мультивалютности

CLAUDE.md с самого начала ограничивал валюты банков/инвентаря/физики парой
RUB/USD с ручным курсом. При явном вопросе "нужны ли другие валюты (EUR и
т.п.)" пользователь не ответил — решение оставлено по умолчанию: **только
RUB и USD**, RUB конвертируется делением на введённый `usd_rub`. Если
понадобится EUR или другая валюта — это будет отдельное расширение
`categoryTotals()` в [src/lib/valuation.ts](src/lib/valuation.ts), не
архитектурная переделка.

## Снимки неизменяемы — в data layer нет функции update

Прямое следствие явного пункта UX в CLAUDE.md ("снимок = иммутабельная запись,
нельзя редактировать прошлое"). `src/lib/snapshots.ts` физически не
экспортирует `updateSnapshot` — не because "не успели", а потому что это
осознанно исключённая возможность. Уникальность `(user_id, period)` в БД
предотвращает случайную перезапись месяца, ошибка от constraint показывается
пользователю как понятный текст, а не как сырой Postgres-код.

## Деплой: две неочевидные ловушки GitHub Actions, которые стоили реального времени

1. **PAT без scope `workflow`** — Windows Git Credential Manager кэшировал
   старый Personal Access Token без разрешения `workflow`. GitHub отклоняет
   пуш файлов `.github/workflows/*` таким токеном с чёткой ошибкой, но фикс
   (добавить scope в существующий токен, не пересоздавать) не очевиден с
   первого раза.

2. **Secrets ≠ Secrets.** GitHub различает **repository-level secrets**
   (Settings → Secrets and variables → Actions) и **environment-level
   secrets** (Settings → Environments → `<env>` → Secrets). Первая попытка
   добавить `VITE_SUPABASE_URL`/`VITE_SUPABASE_ANON_KEY` попала в
   environment-scoped секреты окружения `github-pages` — но job `build` в
   [.github/workflows/deploy.yml](.github/workflows/deploy.yml) не объявляет
   `environment: github-pages` (только job `deploy` его объявляет), поэтому
   секреты были физически невидимы шагу сборки. Собранный бандл при этом не
   падал явной ошибкой — просто тихо содержал `throw new Error('Missing
   VITE_SUPABASE_URL...')` вместо реального URL, что нашлось только через
   прямую проверку содержимого JS-бандла на проде (`grep` по
   supabase.co/project ref), а не через логи workflow (сборка формально
   "зелёная" в обоих случаях).

**Урок:** зелёный workflow run ничего не говорит о том, что итоговый бандл
рабочий, если ошибка — не exception при сборке, а тихий undefined на этапе
рантайма. Проверка "докачаться до реального бандла на проде и погрепать
конкретную строку" оказалась единственным надёжным способом подтвердить факт.

## `.claude/settings.local.json` — в `.gitignore`, `.claude/launch.json` — в репозитории

Одна папка, разная судьба файлов внутри. `settings.local.json` — персональный
кэш разрешённых bash-команд конкретной машины (там же случайно осели полные
curl-команды с anon-ключом в тексте команды — не секрет по сути, но шум в
публичном репо). `launch.json` — легитимный конфиг команды запуска dev-сервера,
общий для любого, кто откроет проект. Разделены явно, а не одним блоком
`.claude/`.

---

## Репозиторий публичный, не приватный

Выбрано пользователем явно ("чтобы можно было работать в нём без оплаты" —
приватные репозитории с GitHub Pages исторически требовали платный план).
Принятый риск: исходный код, включая Supabase anon key, виден всем. Это
осознанно приемлемо, потому что anon key безопасен по дизайну Supabase — он
не даёт доступа к данным без RLS-проверки авторизованной сессии.
